## 0. 总体原则（横切约束）

1. **模型接入统一走 OpenAI 兼容协议**：Embedding / Rerank / LLM 三角色经 model-gateway 封装（`services/model_gateway/`），换模型 = 改 `.env` 配置，不改业务代码。
2. **默认 fake provider**：全部模型默认确定性假实现，零外部依赖即可跑通测试与联调（`infra/config.py`）。
3. **全组件私有化部署**，数据不出内网。
4. 开发语言：**Python 3.11 + FastAPI**。

## 1. 离线知识库

### KB-1 上传

| 项 | 选型 | 理由 | 备选 |
|---|---|---|---|
| API 接入 | FastAPI + python-multipart | 批量 multipart 上传，异步原生支持 | — |
| 原始文件存储 | **MinIO** | 私有化对象存储标准方案，存原始文件与中间产物 | S3 兼容任意云 |
| 异步任务 | **Redis + RQ** | 入库流水线重 IO，与在线问答隔离；运维简单 | Celery、Kafka |
| 幂等 | 文件 sha256 指纹 | 内容未变不重复入库 | — |

### KB-2 标准化（格式统一转换）

| 输入格式 | 选型 | 理由 | 备选 |
|---|---|---|---|
| Markdown | **mistune** | 轻量、保留标题层级 | markdown-it-py |
| HTML | **BeautifulSoup4 + lxml** | 容错好、清洗正文成熟 | trafilatura |
| PDF / 扫描件 | **MinerU**（可选依赖 `parsing-heavy`） | 中文 PDF 版面/表格/OCR 效果最好 | Docling、pypdf |
| Office（Word/Excel/PPT） | **Apache Tika**（可选依赖 `parsing-heavy`） | 一套接口覆盖全系 Office | LibreServer headless |

标准化统一产出：**Markdown 化中间格式 + 结构元数据**（标题层级、页码），供解析环节统一消费。

### KB-3 解析（抽取与切分）

| 项 | 选型 | 理由 |
|---|---|---|
| 切分策略 | **自研标题感知递归切分**（`core/chunking.py`） | 按标题层级切到自然段落边界；块目标 512 token、重叠 64；保留 `parent_id` 支持 small-to-big |
| 表格 | 整表作为一个 chunk，转 Markdown 表格 | 拆表破坏语义 |
| 编排 | **自研薄流水线（纯 Python 函数）** | 主流程仅数个函数调用，不引入 LangChain 的调试与升级负担 | LlamaIndex |

### KB-4 向量化

| 项 | 选型 | 理由 | 备选 |
|---|---|---|---|
| Embedding 模型 | **BGE-M3**（自托管，TEI/vLLM，dim=1024） | 中文效果好、8K 上下文，一次产出 dense+sparse | Qwen3-Embedding、OpenAI text-embedding-3 |
| 向量库 | **Milvus 2.5+**（HNSW + SPARSE_INVERTED_INDEX） | 原生混合检索与标量过滤，500 万 chunk 级成熟 | pgvector（<100 万 MVP 简化） |
| 元数据 | **PostgreSQL 15 + SQLAlchemy 2** | chunk/文档元数据唯一事实源，删改以 PG 为准 | — |

## 2. 智能问答

### QA-1 问题向量化

| 项 | 选型 | 理由 |
|---|---|---|
| 模型 | 与 KB-4 **同一个 BGE-M3**，经 model-gateway `embed()` 调用 | 问/答向量必须同空间；统一入口保证不被漂移 |

### QA-2 向量召回

| 项 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 检索方式 | **混合召回**：dense(top50) ∥ sparse(top50) | dense 管语义、sparse 管关键词，中文场景互补 | 纯 dense |
| 融合 | **RRF（Reciprocal Rank Fusion）** → 候选 30 | 无需调分数量纲，稳健 | 加权分数融合 |

### QA-3 Rerank 排序

| 项 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 模型 | **bge-reranker-v2-m3**（自托管 TEI） | 与 BGE-M3 配套、中文强、单卡可跑 | Cohere Rerank（需外网） |
| 输出 | 精排取 **top 5~8** 作为生成上下文 | 控制 prompt 长度与噪声 | — |

### QA-4 生成回答

| 项 | 选型 | 理由 | 备选 |
|---|---|---|---|
| LLM | **Qwen2.5-7B-Instruct**（vLLM 推理），轻任务用 Qwen2.5-1.5B | 私有化、OpenAI 兼容、单卡可跑 | 公司网关 / GPT / Claude（合规允许时） |
| 流式输出 | **SSE（sse-starlette）**，以 `refs` 事件收尾 | 首 token 体验；前端渲染引用卡片 | WebSocket |
| 防幻觉 | Prompt 强制"仅上下文内回答 + [n] 引用编号"；检索为空明确说未找到 | 对应需求"仅根据离线知识回答" | — |

## 3. 支撑设施（横切）

| 组件 | 选型 | 用途 |
|---|---|---|
| 元数据库 | PostgreSQL 15 | 文档/chunk/会话/审计元数据 |
| 队列 | Redis + RQ | 入库任务（重试/幂等） |
| 对象存储 | MinIO | 原始文件、解析中间产物 |
| 可观测 | Langfuse（自托管）+ Prometheus | LLM 全链路 tracing、指标监控 |
| 评估 | RAGAS + 自建黄金问答集 | 忠实度/相关性/召回率量化 |
| 部署 | Podman Compose（一期）→ K8s（二期） | 见设计书 §10 |
