## 1. 系统定位

构建一个 **RAG 系统**，包含两大能力：

1. **离线知识库**——将企业文档加工为可检索的向量知识资产；
2. **智能问答**——基于离线知识库回答用户问题，回答有据可依。

```
        ┌──────────── 离线知识库 ────────────┐
文档 ──▶│ 上传 → 标准化 → 解析 → 向量化 │──▶ 向量知识库
        └────────────────────────────────────┘

        ┌──────────── 智能问答（在线） ────────────────────┐
问题 ──▶│ 问题向量化 → 向量召回 → Rerank 排序 → 生成回答 │
        └──────────────────────────────────────────────────┘
                      ▲
                      └── 依据：离线知识库
```

## 2. 功能需求

### 2.1 离线知识库（入库流水线）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| KB-1 | 上传 | 支持常见格式文档（PDF/Word/Markdown 等）上传至知识库 | P0 |
| KB-2 | 标准化 | 将不同来源/格式的文档统一转换为标准中间格式，便于后续统一处理 | P0 |
| KB-3 | 解析 | 从标准化产物中抽取正文内容，按策略切分为 chunk，保留出处信息 | P0 |
| KB-4 | 向量化 | 对 chunk 批量生成 embedding 向量，写入向量库，与元数据关联 | P0 |

流水线顺序：**上传 → 标准化 → 解析 → 向量化**，任一环节失败可重试、可追溯状态。

### 2.2 智能问答（在线链路）

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| QA-1 | 问题向量化 | 用户问题使用与文档一致的 embedding 模型转向量 | P0 |
| QA-2 | 向量召回 | 在向量库中检索与问题最相似的 topK chunk 作为候选 | P0 |
| QA-3 | Rerank 排序 | 对候选 chunk 用 rerank 模型精排，取 top N 作为生成上下文 | P0 |
| QA-4 | 生成回答 | **仅根据离线知识回答**：回答须有知识库内容支撑；知识库中无相关知识时，明确告知未找到，不得编造 | P0 |

## 3. 验收要点

1. 一个文档走完"上传→标准化→解析→向量化"后，可被问答检索命中；
2. 针对知识库内容提问，回答正确且可溯源到来源文档；
3. 针对知识库之外的问题，系统回答"知识库中未找到"，无凭空编造。
